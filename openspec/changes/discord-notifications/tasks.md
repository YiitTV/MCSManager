# Tasks

## Parallelism and shared contract

Groups A (Daemon), B (Panel backend), C (Frontend), and D (Docs/receiver) can be implemented in parallel by different agents. They share only the contract in `design.md`: section 8 (daemon `instance/lifecycle` message) between A and B; sections 5, 6, and 7 (payload, signature algorithm, HTTP API and settings shape, internal `emitNotification`) between B, C, D, and E. Each group develops against fakes of the other side (B against a fake daemon packet, C against a mocked API module, D against sample payloads and signatures). Group E (Integration) starts after A and B pass their suites. Task B6 (group runner hook) must wait until the `instance-groups` change is merged; the `instance-backups` change only calls `emitNotification` and is not touched here.

## A. Daemon (independent)

- [ ] A1. Add a daemon notifier (`daemon/src/service/panel_notifier.ts`) that keeps a `Set` of sockets authenticated as the panel (add in `auth_router.ts` after `loginSuccessful`, remove on socket disconnect) and exposes `notifyPanels(event, data)` sending only to that set, plus a `daemonShuttingDown` flag set at the start of `InstanceSubsystem.exit`/`softExit` and the signal handler. Unit test: unauthenticated and stream sockets receive nothing; the set is cleaned on disconnect. Then `cd daemon && npm test`.
- [ ] A2. In `Instance.stopped(code)`, compute `expected = status === STOPPING || eventTask.ignore || daemonShuttingDown` before `ignore` is reset, and emit `instance/lifecycle` with `kind` `stopped` or `crashed` (with `exitCode` and `willAutoRestart` computed from the existing auto-restart conditions). Unit tests with a fake instance cover crash, requested stop, kill, restart, shutdown, and auto-restart limits. Then `cd daemon && npm test`.
- [ ] A3. Emit `started` from `started()`; record `pendingAutoRestart` before the auto-restart `execPreset("start")` and emit `auto_restarted` (with `attempt`, `maxAttempts`) instead of `started` on the next open, clearing the flag on start failure. Unit tests: manual start gives `started`, auto-restart start gives only `auto_restarted`. Then `cd daemon && npm test`.
- [ ] A4. Run the lifecycle suites required by the `mcsmanager-test` skill because `instance.ts` changed (`cd daemon && npm test` and `npm run test:integration` per the skill) and confirm no regression in start/stop/restart behavior.

## B. Panel backend (independent of A, C, D)

- [ ] B2. Add the config model and persistence (`NotificationConfig` entity with defaults, load/store through `Storage.getStorage()`, validation of limits: 9 event keys, 200 exclusions, `panelName` length), masking helper using `"__MCSM_SECRET_DATA__"`, and secret generation (`randomBytes(32)` hex). - [ ] B3. Add the event builder and sinks: payload construction (design section 5, truncation, 8 KB cap), HMAC signing helper (`signBody(secret, tsSec, bodyBuf)`), `bot_http` sender and `discord_webhook` sender with `renderDiscordEmbed`, using Node `https`/`http`, pinned lookup, 10 s timeout, 2 KB response cap, no redirects, safe error codes. Unit tests: known-answer signature vector (also reused by D2), embed escaping and `allowed_mentions`, redirect treated as failure, no URL/secret in thrown errors or logs. Then `cd panel && npm test`.
- [ ] B4. Add `notification_service.ts`: `emitNotification` (sync, never throws), filtering (enabled, sink, toggle, exclusion), per-instance coalescing with `suppressedBefore`, bounded queue (200, drop-oldest), single worker with `nextAttemptAt` retries (5/30/120 s, `Retry-After`), one re-armed timer, stats and last delivery. Unit tests with fake timers and a fake sender: retry schedule, permanent 4xx, overflow, flood of 20 crashes yields 6 sends then `suppressedBefore`, a pending retry does not block a ready event. Then `cd panel && npm test`.
- [ ] B5. Add `notification_router.ts` (`GET/PUT /config`, `POST /secret/rotate`, `POST /test` with `speedLimit`), register it with the other routers, add an operation-log entry without values, and subscribe to `instance/lifecycle` in `RemoteService.connect()` with strict validation, mapping to event types, and `daemonId`/`daemonName` resolution. Router tests: regular user and anonymous are refused on every route, masked placeholders, rotate returns plaintext once, validation errors. Then `cd panel && npm test` and `cd panel && npm run build`.
- [ ] B6. (After `instance-groups` is merged.) Call `emitNotification` from `instance_group_runner.ts` for `group.run_started`, `group.run_finished` (succeeded and cancelled), and `group.run_failed` at the existing state transitions, in a try/catch so a failure cannot affect a run.
